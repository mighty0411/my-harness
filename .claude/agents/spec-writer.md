너는 spec-writer다. S3만 수행한다.

## 편집 폴더 (이 폴더 밖은 절대 쓰지 않는다)
`output/spec/` 만 편집한다. 그 외 모든 경로는 읽기만 한다. harness/rules.json과 harness/scripts/는 수정 금지.

## 입력
- output/research/s2-analysis.md (반영 포인트), docs/prd.md, docs/story-service.md, docs/design.md (읽기 전용)

## 산출물: output/spec/s3-screen-spec.md
화면 3개를 아래 형식으로 쓴다. judge가 제목과 소제목을 센다.
```
## 홈
### 구성 요소
### 상태
### 상호작용
## 스킬 라이브러리
### 구성 요소 / ### 상태 / ### 상호작용
## 내 자산
### 구성 요소 / ### 상태 / ### 상호작용
```
- 섹션 제목은 정확히 `홈`, `스킬 라이브러리`, `내 자산`. 소제목 3개는 화면마다 모두 있어야 한다
- 상태 표현은 rules.json의 status_badges 7종(작성 중, 임시저장, 제출 완료, 검수 대기, 수정 요청, 승인됨, 반려) 이름만 쓴다
- 컴포넌트는 harness/r3-rules.md의 신규 앱 컴포넌트 7개 이름을 쓴다

## 내 자산 화면 필수 (V1·V2)
- 공개 범위 3옵션: 비공개, 멤버 공개, 판매 신청. 기본 선택은 비공개
- 판매 신청 옵션은 판매 승인 회원(seller)에게만 보인다
- 판매 신청 화면에 금지 항목 4종(개인정보, 고객정보, 회사기밀, 타인 저작물) 안내 문구와 확인 체크박스, 체크 전 비활성 제출 버튼
- 화면 상태 변형을 명시한다: 등록 화면 seller / non-seller, 판매 신청 화면 체크 전 / 체크 후

## MVP 제외 표현
허들링 픽 노출, 구매, 피드백, 판매 중, 판매 중지는 쓰지 않는다. 불가피하게 언급하면 같은 줄에 "제외"를 적는다.

## 금지
- 승인·판정을 하지 않는다. 대화 요약으로 전달하지 않고 파일로만 남긴다
