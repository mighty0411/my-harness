# 작업 워크플로우 (AI 없이 손으로 했던 마지막 경험)

`story-service.md`는 "무엇을 위한 일인지"의 기준이고, 이 문서는 "내가 실제로 어떻게 했는지"를 기록한다. 둘은 별개다.

디자인 가이드 기준 문서: `design.md`

| # | 누가 | 무엇을 | 한다 |
|---|---|---|---|
| 1 | 나 | uibowl에서 경쟁사 레퍼런스를 | 수집한다 |
| 2 | 나 | 레퍼런스를 토대로 분석하고 우리 서비스에 반영할 부분을 | 가져온다 |
| 3 | 나 | 분석 내용을 토대로 우리 서비스 화면 설계 문서를 | 구체화한다 |
| 4 | 나 | 레퍼런스와 화면설계서를 반영한 UI 키스크린 2~3개를 Figma에 390×844 사이즈로 | 그린다 |
| 5 | 나 | 내부 관계자들과 협의 후 컨셉 시안을 | 확정한다 |
| 6 | 나 | 컨펌된 시안을 기반으로 디자인 토큰과 컴포넌트를 제작하고, 화면 디자인에 | 들어간다 |
| 7 | 나 | 완성된 시안에서 토큰이나 컴포넌트가 `design.md`에 위반된 부분이 없는지 | 검토한다 |

## 명사 · 게이트 · 경계

- 명사: 문장에서 나오는 산출물
- 게이트: 멈칫한 지점, 또는 다음 단계로 넘어가기 전 반드시 필요한 확인
- 경계: 내 손에서 다른 도구·사람·문서로 넘어가는 지점

| 문장 | 명사 | 게이트 | 경계 |
|---|---|---|---|
| 1. uibowl에서 경쟁사 레퍼런스를 수집한다 | 경쟁사 레퍼런스 | - | uibowl (도구) |
| 2. 레퍼런스를 분석하고 반영할 부분을 가져온다 | 분석 내용, 반영할 부분 | 멈칫함: 반영할 부분 선정에 컨펌 필요 (구조적으로 항상 필요 · 통과해야 ③ 진입) | 없음 |
| 3. 화면 설계 문서를 구체화한다 | 화면 설계 문서 | 구조적으로 항상 필요: 화면설계 확정 후 디자인 제작(④)으로 넘어가기 전 | 없음 |
| 4. Figma에 UI 키스크린 2~3개를 390×844로 그린다 | UI 키스크린 2~3개 | 멈칫함: 컨펌 필요 | Figma (도구) |
| 5. 내부 관계자들과 협의 후 컨셉 시안을 확정한다 | 컨셉 시안 | 협의 후 확정 | 내부 관계자 (사람) |
| 6. 컨펌된 시안으로 토큰·컴포넌트를 제작하고 화면 디자인에 들어간다 | 디자인 토큰, 컴포넌트, 화면 디자인 | 위 게이트로 진입 조건 충족 (새 게이트 없음) | Figma (도구) |
| 7. 완성된 시안이 `design.md`를 위반하지 않았는지 검토한다 | (산출물 명사 없음) | `design.md` 준수 검토 | `design.md` (문서, 기준 대조) |

## 요약

|---|---|

| 에이전트 경계 | 도구: uibowl(①), Figma(④⑥) / 사람: 내부 관계자(⑤) / 문서: `design.md`(⑦, 기준 대조) |
