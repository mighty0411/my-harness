# R2. 단계

참조: docs/story-work.md (7단계를 8단계로 옮김: ⑥을 S6·S7로 분리)

## 실행 방식
- 단계 단위 실행. 각 단계 끝에서 통과 조건 충족 시 자동으로 다음 단계 진행 (통과 조건은 R5에서 확정)
- S5에서만 정지. 사람이 "확정"을 입력하면 이어짐
- 3개 화면(홈, 스킬 라이브러리, 내 자산)을 한 세트로 S1~S8 진행. 화면별 병렬 없음
- S7은 이번 3개 화면까지만 완성. PRD 16장의 나머지 화면은 범위 밖

## S8 이후 컬러 변경 (초안 컬러 규칙의 예외 길)
- 초안(S1~S8)은 처음 지정한 컬러를 그대로 쓴다. 이 단계에서는 컬러 예외를 만들지 않는다
- S8이 passed인 뒤에만 컬러 변경을 열 수 있다. 사람이 "컬러 변경: 위치와 색"을 말하면 시작한다
- 순서: ① 요청 위치·색·글자색을 확인하고 design.md 컬러 문구를 먼저 고친다 → ② 컴포넌트(S6) 수정, 없으면 컴포넌트를 만든다 → ③ 화면(S7) 수정 → ④ 변경분 덤프 갱신 후 G6·G7·G8 재판정
- 새 Figma 페이지는 만들지 않는다. S6·S7 기존 페이지에서 수정한다
- 컬러 변경이 harness/rules.json(허용 색, accent 상한, D03 CTA 금지 등)과 부딪히면 임의로 우회하지 않는다. 사람이 규칙 수정을 승인하면 rules.json과 판정 스크립트를 고치고 테스트를 통과시킨 뒤 재판정한다
- 기록: r0-context.md에 회차, 위치, 색, 보류 항목을 남긴다. 변경 전 S8 통과본으로 돌아가려면 "수정 요청"이나 git 이력을 쓴다

## 실행 시작 입력값
- 대상 화면: 홈, 스킬 라이브러리, 내 자산
- 경쟁사: 지정하면 그대로 사용. 미지정 시 uibowl 검색 상위 3개 자동 사용
- 사람 승인은 S5 1곳뿐 (경쟁사 지정은 승인이 아니라 입력값)
- 시안 수(variants): 화면마다 만들 안의 수. 1이면 기존 방식(화면당 시안 1개를 그대로 확정), 2~3이면 안 방식(S4에서 화면마다 2~3안, S5에서 화면마다 하나 선택). state.json input.variants, 기본 1. 시작할 때 `state.py init --variants N`
- 안 방식에서 S6·S7은 선택한 안만 입력으로 쓴다. 고르지 않은 안은 S4·S5 페이지에 남긴다
